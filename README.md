# aed
긴급 재설정 명령어 모음

- `./status`: 시간·네트워크 상태, 저널 사용량·부팅 기록과 Docker 사용량, 태그 없이 남은 이미지 후보를 표시한다.
- `./run`: 시간·네트워크·저널 설정을 적용하고 Docker 이미지 정리를 실행한다.

Docker 명령이 없으면 해당 작업을 건너뛴다. Colima 등 실행 환경에 관계없이
현재 사용자의 Docker 연결 설정을 사용한다. 연결할 수 없으면 오류를 표시한다.
Docker 작업은 사용자 권한으로 실행하며, Linux 시스템 설정에 필요한 권한만
`sudo` 명령으로 요청한다. Linux 외 환경에서는 시스템 설정을 건너뛴다.

이미지 정리는 `docker image prune` 명령을 사용하고 기본 확인 질문을 유지한다.
태그 없이 남은 이미지 중 컨테이너가 참조하지 않는 이미지를 정리한다.
조회한 후보가 실행 시점의 삭제 목록과 완전히 같지는 않을 수 있다.
삭제 결과와 확보한 공간은 Docker 명령의 출력으로 확인한다.

저널 설정은 `aed.conf` 파일에서 변경한다. 기본값은 영구 저장, 사용량 제한
`200M`, 여유 공간 기준 `500M`, 최대 보관 기간 `30day` 이다.

| 항목 | 설명 |
| --- | --- |
| `JOURNAL_STORAGE` | `persistent`: 디스크 저장, `volatile`: 메모리 저장, `auto`: `/var/log/journal` 디렉터리가 있으면 디스크 저장, `none`: 저장 중지 |
| `JOURNAL_SYSTEM_MAX_USE` | 디스크 저널 사용량 제한. 바이트 또는 정수 뒤에 `K`, `M`, `G`, `T`, `P`, `E` 사용 가능. 단위는 1024 기준 |
| `JOURNAL_SYSTEM_KEEP_FREE` | 저널이 디스크에 남겨 둘 여유 공간 기준. 사용량 제한과 같은 단위 사용 |
| `JOURNAL_MAX_RETENTION_SEC` | 최대 보관 기간. 초 또는 정수 뒤에 `s`, `min`, `h`, `day`, `week`, `month`, `year` 사용 가능. `0` 값은 기간 제한 해제 |

`JOURNAL_STORAGE` 항목과 나머지 저널 항목을 모두 비우거나 생략하면 변경을
건너뛴다. 이미 적용한 설정 파일은 유지한다. 저장 방식을 지정한 상태에서 나머지
항목을 비우면 해당 항목은 생성하는 파일에서 제외하고 시스템의 다른 설정을 따른다.

`./run` 실행 시 `/etc/systemd/journald.conf.d/90-aed.conf` 파일을 저장하고
`systemd-journald` 서비스를 재시작한다. 영구 저장과 자동 모드에서는
`journalctl --flush` 명령으로 현재 메모리의 로그를 디스크로 옮긴다.
자동 모드에서는 영구 저장 디렉터리가 있을 때만 옮긴다.
기존 설정 파일은 유지하지만, 이름순으로 뒤에 오는 추가 설정 파일이 있으면
그 설정이 우선할 수 있다. 기본 저널 네임스페이스에 적용한다.

재부팅 후 `sudo journalctl --list-boots` 명령으로 이전 부팅 기록을,
`sudo journalctl -b -1` 명령으로 이전 부팅의 로그를 확인할 수 있다.
`./status` 출력은 현재 사용자에게 조회 권한이 있는 로그만 포함한다.
이미 소실된 로그는 복원하지 못하며, 용량·기간 제한에 따라 오래된 로그가
자동 정리되므로 지정 기간의 보관을 보장하지는 않는다.
메모리 저장으로 바꿔도 기존 디스크 로그는 직접 삭제하지 않는다.

라즈베리파이에서도 실제 저장 여부는 설치된 운영체제의 설정에 달려 있다.
`auto` 모드에서 영구 저장 디렉터리가 없거나 `volatile` 모드이면
재부팅할 때 로그가 사라진다. `persistent` 모드도 `/var/log/journal`
경로가 쓰기 가능한 디스크에 있어야 재부팅 후 로그를 보존할 수 있다.
저장 방식과 보관 제한은 [공식 문서](https://www.freedesktop.org/software/systemd/man/257/journald.conf.html)를 참고한다.
